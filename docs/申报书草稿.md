## 需求与实现

地图服务区或编辑器需要判断点是否属于区域：近共线坐标可能导致浮点判定失误，凹形和孔洞又会让包围盒产生误命中。项目从 MoonBit 脚手架出发，于十月实现可复用的平面区域查询：

- 方向判定先做浮点筛选，不确定时用标准库 BigInt 精确计算输入二进制坐标的符号；提供线段关系和点的内部／边界／外部判定。
- 实现可插入、删除和范围查询的动态 R-tree，包含二次分裂、删除重整和结构检查。
- 在包围盒筛选后检查真实区域，识别孔洞、凹形误命中，并返回边界环、边编号和索引版本。

## 验证与使用

运行 `moon run examples/service_area --target js`：模拟点落在排除区、边界策略、区域更新后重新命中和区域删除；示例包含断言。[GitHub Actions](https://github.com/ZYK-ai-nb/moon-geo/actions) 记录多后端检查。180 个 Python Fraction 样本核对方向符号；503 对线段和 507 个点与 Shapely/GEOS 对照；动态索引与逐项扫描对照。GEOS 样本只覆盖小整数及三个区域，不能证明全部输入正确。

## 同类与范围

已有 [MoonGeoKit](https://github.com/cn-xjr/moongeokit)、[moon-geometry](https://github.com/walkzzz/moon-geometry)、[MoonSTRtree](https://github.com/LING71671/MoonSTRtree)，几何或索引功能有实质重合。MoonGeo 聚焦精确方向回退、动态 R-tree 和区域诊断的组合；[对照说明](https://github.com/ZYK-ai-nb/moon-geo/blob/main/docs/related-work.md)限定具体版本和抽查范围，不宣称首创或整体领先。

实现参考 Shewchuk 鲁棒谓词和 Guttman R-tree；库仅依赖 MoonBit 标准库。坐标需处于同一平面；面积、质心和距离为浮点近似，不提供经纬度投影或多边形布尔运算。开发使用 AI 辅助设计、代码、测试与文档；参赛者需理解技术选择并对结果负责。
