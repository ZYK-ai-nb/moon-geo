## 一、项目需求与应用场景

地图编辑器、服务范围管理等系统，需要判断一个位置是否属于某个区域，并在区域调整后得到一致的查询结果。实际处理中，服务区可能是凹形，也可能包含不服务的内部区域；只判断点是否落在外包矩形内，会把排除区域误判为命中。边界归属也可能因业务规则不同而改变。坐标接近共线时，普通浮点叉积还可能丢失方向符号，影响几何判定。

MoonGeo 提供可复用的平面几何和动态空间查询能力，帮助调用方区分区域内部、外部和边界，并检查查询结果的依据。项目示例使用自建的模拟坐标，不把它当作真实用户案例。

## 二、本期完成的工作

项目从 MoonBit 脚手架起步，十月新增以下实现：

1. **几何判定**：提供点、线段、多边形及含孔区域的基础运算。方向判定先使用浮点筛选；结果不确定时，利用 MoonBit 标准库 BigInt 精确计算输入二进制坐标的方向符号。线段关系覆盖端点触碰、共线重叠及零长度情形。
2. **动态空间索引**：实现 R-tree 插入、删除和范围查询，包含二次分裂、删除后重整与结构检查。调用方无需预先设置固定的全局索引范围，但坐标仍受本库规定的数值范围约束。
3. **区域查询与诊断**：先通过包围盒筛选候选，再检查真实区域；返回命中结果、边界环和边编号，并记录索引版本。调用方可以决定边界是否计入命中，诊断信息仍会保留。

## 三、与已有项目的关系

MoonBit 已有 [MoonGeoKit](https://github.com/cn-xjr/moongeokit)、[moon-geometry](https://github.com/walkzzz/moon-geometry) 和 [MoonSTRtree](https://github.com/LING71671/MoonSTRtree)，它们在几何、索引或区域查询上与本项目有实质重合。MoonGeo 聚焦精确方向回退、动态 R-tree 维护和区域边界诊断的组合。

例如，抽查版本的 MoonGeoKit 网格索引使用预设世界范围；MoonGeo 的 R-tree 不要求预先设定该范围。这个比较仅针对所查的网格索引，不代表对方其他索引不具备相应能力，也不证明性能优劣。各项目固定版本和源码入口见[同类调研](https://github.com/ZYK-ai-nb/moon-geo/blob/main/docs/related-work.md)；本项目不宣称生态首创或全球唯一。

## 四、运行、验证与边界

已发布 `ZYK-ai-nb/moon-geo@0.1.1`。运行 `moon run examples/service_area --target js`，可以复现排除区域内的点未命中、边界排除、更新后重新命中及删除区域等过程，示例包含断言。[GitHub CI](https://github.com/ZYK-ai-nb/moon-geo/actions/runs/41002762647) 在 Wasm、Wasm-GC、JS、Linux Native 四个后端各通过 93 项测试；180 个 Python Fraction 样本核对方向符号，503 对线段和 507 个点与 Shapely/GEOS 对照，索引查询与逐项扫描对照。GEOS 样本限于小整数和三个区域，不能证明全部输入正确。

运行库仅依赖 MoonBit 标准库，参考 Shewchuk 鲁棒谓词思路和 Guttman R-tree 论文。坐标须处于同一平面，面积、质心和距离是浮点近似；经纬度投影及多边形布尔运算不在本期范围。开发使用 AI 辅助设计、代码、测试和文档，参赛者需理解技术选择并对最终质量负责。
