## 本地已完成的工作

1. `geojson/` 接收 FeatureCollection 中的 Polygon、MultiPolygon。校验闭合环、唯一 Int32 ID、二维坐标和核心拓扑，重新计算包围盒。整个集合校验成功后才建立新索引。
2. `workflow/` 接收初始区域和按序操作，支持 query、insert、replace、remove。输出命中 ID、内外边界决策、环和边编号、索引版本、实际遍历计数与结构错误。
3. `app/` 导出 MoonBit 生成的 JS 模块，Node 文件入口只做构建和输入输出。运行库仍仅依赖 MoonBit 标准库。CLI 需要 Node.js，开发对拍需要 Shapely。
4. 接入固定提交的 Natural Earth 真实公开几何，取 South Africa、Lesotho 两个区域。保留其孔洞，生成查询探针和人为更新测试。数据并非客户案例，测试中的更新不是行政边界变化。

## 一条命令运行

在项目根目录执行：

```sh
node scripts/query_geojson.mjs testdata/geojson-demo.json work/geojson-result.json
```

结果中的四次查询依次命中 `[102]`、`[101,102]`、`[101]`、`[101,102]`。其间执行替换、删除和重新插入，最后版本号为 5，结构检查无错误。

请求具有 `regions` 和 `operations` 两个字段。`regions` 是 FeatureCollection，每个 Feature 使用唯一整数 `id` 和 Polygon 或 MultiPolygon 几何。操作格式如下。

```json
{"op":"query","point":[28.2,-29.6],"include_boundary":true}
```

`insert`、`replace` 使用 `regions` 字段提供只含一个 Feature 的集合，`remove` 使用 `id`。缺失 ID 的删除或替换返回 `changed=false`。非法操作返回错误，后续操作继续。单次修改验证失败时索引保持原状态，之前已成功的操作仍然保留。CLI 遇到任意操作失败返回退出码 1，并保留逐项报告。顶层 `ok=true` 仅表示请求已被处理，需同时检查每项 `ok`。返回的环与边编号对应核心规范化环，`ring=0` 为外环。

```sh
moon check --target all --deny-warn

```

独立验证需先在开发环境安装 `shapely==2.2.0`。本机已安装在忽略的 `work/shapely-oracle`，PowerShell 可设 `$env:PYTHONPATH='work/shapely-oracle'`。普通库测试和文件 CLI 不依赖 Shapely。

Natural Earth 对照包含 409 次点查询，验证命中和三态决策，以及一次故意无效更新后的版本不变。网格对照包含 256 个区域和 256 次查询，分别检查正确 ID、结构和实际工作量。当前网格结果为 1376 次包围盒条目检查、256 次区域精化。固定全扫描流程需要 65536 次区域判断。这些操作类型和成本不同，计数不能推导耗时提升，也不代表超过其他空间索引。

## 公开边界

GeoJSON 入口是 RFC 7946 的应用子集。只接受经度在 [-180,180]、纬度在 [-90,90] 的二维输入，按经纬坐标的直线段做平面拓扑判定。拒绝跨日界线、环经度跨度超过 180 度、自定义 CRS、三维位置、空几何、相交或触碰的 MultiPolygon 分量，以及重复 JSON 键。要求整数 ID 是应用约束，RFC 本身也允许字符串 ID。

不作全球或球面拓扑、米制距离、完整 GeoJSON 支持的声明。`properties` 不参与查询，传入 `bbox` 被忽略并重算。环校验仍为二次复杂度，文件 CLI 会完整读入请求，尚无大文件流式或并发修改保证。Natural Earth 的小比例尺边界仅用于兼容验证。
